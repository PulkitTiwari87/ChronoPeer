Method

Six steps. Each one repeatable.

  1. 01

    Verify

    Recompute the SHA-256 of every file. The script stops on a mismatch.

  2. 02

    Parse

    Read the Sysmon events from the three EVTX files.

  3. 03

    Order

    Sort by the event time Sysmon logged, not by record order.

  4. 04

    Number

    Label events T01 to T25 and write inferences I1 to I9.

  5. 05

    Challenge

    A reviewer gives an alternative explanation for each inference.

  6. 06

    Revise

    Change the claim, and log every decision with its reason.

Peer critique

Every inference gets an alternative.

The reviewer is an AI (Claude), so this is a critique round, not a human peer. 10 items were challenged and answered against the events.

I1Upheld: actor claim stays Low; host/log claim stays Medium.

Reviewer’s challenge

Same host and log does not show the same actor. Record IDs interleave in time, but C has no network link to 10.0.2.19.

What the logs show

Logon IDs: A=0x3e7 (SYSTEM), B=0x1d313d (IEUser), C=0xffe4 (IEUser processes) and 0x3e7 (SYSTEM service VSSVC); the two IEUser sessions differ, and 0x3e7 is the shared SYSTEM session, which does not identify an actor; 11 and 315 record IDs missing between files.

What would tell them apart

A network or logon event in C tying it to 10.0.2.19 (absent).

Challenge strength: SupportedClaude (AI reviewer) · 2026-11-17
I2Partly upheld: service creation stays High; remote SMB origin lowered to Medium.

Reviewer’s challenge

Remote origin rests on a 335 ms gap between T01 (inbound SMB) and T03 (service registry write). No shared session ID links them.

What the logs show

T02 shows the \ntsvcs pipe opened by System; file A contains no sc.exe process record, which argues against a local sc create. But the files are excerpts, so absence is weak.

What would tell them apart

Security 4624/7045 events or a full Sysmon log showing no sc.exe.

What the logs show

I8Upheld: stays Low; timestomping unsupported (v2 wording already narrow).

Reviewer’s challenge

Sysmon event 2 records any creation-time change and does not show intent. Both events set the same value, which is what copying a package while keeping its original creation time would produce.

What the logs show

T18 (Temp\302a23.msi) and T20 (C:\Windows\Installer\304d1c.msi) both set CreationUtcTime to 22:43:38.892, 5 min 20 s before T18. T18 and T20 are the only event-2 records among the 25 events. Checked against timeline.csv; raw EVTX not re-read.

What would tell them apart

The source package's own creation time, or $MFT $STANDARD_INFORMATION vs $FILE_NAME times (neither is in these logs).

I9Upheld: stays Rejected; VSSVC start shows no tampering.

Reviewer’s challenge

Starting VSSVC.exe shows the Volume Shadow Copy service started. It does not show a shadow copy was created, changed or deleted, and no shadow-copy command appears in the 25 events.

What the logs show

T19: services.exe starts VSSVC.exe 0.25 s after T18 (msiexec event). No vssadmin, wmic or diskshadow process creation in any of the 25 events (searched timeline.csv). The files are excerpts, so absence is weak.

What would tell them apart

VSS or System log events, vssadmin list shadows before and after, or a deletion command in a full Sysmon log.

Limitations

What these logs cannot show.

  • Excerpts, not full logs

    11 record IDs are missing between files A and B, and 315 between B and C. Absence of an event is not evidence of absence.

  • Sysmon only

    There is no Security log, so no record of which account authenticated, and no packet capture, so no payload content.

  • Labelled lab data

    File names such as meterpreter and psexec can bias the reading. They were treated as labels, not evidence.

  • One AI reviewer

    The reviewer was an AI. It shows where the reasoning is weak, not that the rest is safe. I8 and I9 were challenged in a later pass. A human reviewer can add a second round.
